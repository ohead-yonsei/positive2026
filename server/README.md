# 이벤트 서버 배포

## 실시간 긍정 퀴즈 (2026-10-28 추가)

- 같은 Apps Script 프로젝트에 `Quiz.gs`를 추가하고 `Raffle.gs`, `Vote.gs`를 함께 업데이트한다. 기존 `Code.gs`의 ScriptLock과 운영진 비밀번호를 재사용한다. 같은 웹 앱 URL의 새 버전을 먼저 배포한 뒤 `index.html`, `quiz.js`, `quiz.css`, `vote.js`를 게시한다.
- 공개 API는 모두 `a: 'gift'`이며 `quizStatus`, `quizJoin`, `quizAnswer`를 사용한다. 본인 이름 index `i`로 입장하고, 게임 ID `runId`와 문제 번호 `round`로 오래된 제출을 차단한다. 이름별 답안은 서버에 저장되어 브라우저를 바꿔도 이어진다. 비밀번호 없는 신뢰 기반 참여이므로 본인 이름을 골라야 한다.
- `#admin`의 운영진 진행실에서 문제 작성·수정·순서 변경 후 저장한다. O/X, 보기 4개의 객관식, 보기 3~6개의 순서 문제를 최대 20개까지 지원한다. 순서 문제는 정답 순서로 입력하며 참가자에게는 섞어서 표시한다. 문제를 작성하기 전에는 연습용 예시 3문제가 준비되어 있다.
- 진행은 `입장 열기 → 첫 문제 → 정답 공개 → 다음 문제 → 최종 순위`다. 정답 공개 순간 제출을 마감하며, 미제출자가 있으면 운영진에게 확인을 받는다. 퀴즈 진행 중 문제 수정은 차단한다. 새 게임 준비 시 지난 게임 기록을 보관한다.
- 운영진 API `quizAdmin`, `quizSave`, `quizOpen`, `quizQuestion`, `quizReveal`, `quizNext`, `quizFinish`, `quizPrepare`는 비밀번호가 필요하다. 변경 요청은 `revision`이 일치할 때만 처리해 버튼 연타나 오래된 관리자 탭이 문제를 건너뛰지 못하게 한다.
- 공개 전 응답에는 현재 문제와 보기만 포함한다. 정답·설명·다음 문제·문제 목록은 반환하지 않는다. 순서 문제의 공개 보기 ID도 표시 순서를 사용하므로 정답 순서를 노출하지 않는다. 운영진이 공개하면 현재 문제 정답과 설명만 반환한다.
- 서버가 정답당 10점, 미제출·오답 0점으로 채점한다. 속도 가산점은 없고 동점은 공동 순위다. 이미 제출한 답안은 수정되지 않으며 재전송 시 중복 저장하지 않는다. 최종 순위는 운영진이 종료했을 때 공개한다.
- 활성 퀴즈는 이전 응답이 끝난 후 약 2.5초 간격으로 조회한다. Apps Script 통신 시간만큼 지연될 수 있다. 백그라운드 탭은 조회를 쉬고 다시 보이면 즉시 연결한다. 새로고침 버튼과 저장·연결 상태를 제공한다.
- 문제와 답안을 별도 Script Properties에 저장해 속성 하나의 크기 제한을 지킨다. 실제 퀴즈 시작이나 운영 투표 공개 없이 로컬 가짜 서버에서 전체 흐름을 검증하고, 실서버에서는 읽기 전용 상태 조회만 수행한다.

## 10주년 긍정 투표 (2026-10-28 추가)

- `Vote.gs`를 같은 Apps Script 프로젝트에 추가하고 `Raffle.gs`도 업데이트한다. 기존 `giftAction → raffleAction` 경로와 `Code.gs`의 ScriptLock을 재사용한다. 비밀 정보가 있는 Code.gs/Gift.gs는 수정하지 않는다.
- `a: 'gift', op: 'voteStatus'`는 참여한 이름 index, 총 참여자 수, 서버 시각과 공개 시각만 반환한다. `voteSubmit`은 `i`와 정확히 세 개의 참가자 index인 `choices`를 받는다.
- 이름별 한 번만 제출할 수 있으며 제출 후 수정할 수 없다. 같은 요청의 재시도와 다른 브라우저의 중복 제출은 기존 표를 변경하지 않고 완료 상태를 반환한다. 비밀번호 없는 이름 선택 방식이라 다른 사람의 이름을 고르는 행위까지 인증으로 막지는 않는다.
- 2026-10-31 21:00:00 한국 시간에 마감하고, 그 시각부터 부문별 11명의 득표수만 반환한다. 별도 트리거 없이 서버 시각으로 판정한다. 운영진이 먼저 공개하지 않는 한 그 전에는 집계 데이터가 응답에 포함되지 않는다.
- `#admin`에서 `투표 마감 · 결과 미리 공개`를 누르면 기존 운영진 비밀번호로 `voteReveal`을 요청한다. 공개 시각을 서버에 영구 저장하고 즉시 투표를 마감한다. 다시 숨길 수 없으며 기존 표는 유지된다. 미리 공개하지 않으면 예정된 시각에 자동 공개된다.
- 개인의 선택 내역은 공개 API에서 반환하지 않는다. 서버 소유자는 Script Properties의 원본을 볼 수 있으므로 운영진도 볼 수 없는 암호화 투표는 아니다.
- 세 부문은 각각 한 명을 고른다. 여러 부문에서 같은 사람을 선택할 수 있다. 동률은 공동 1위, 투표가 없으면 수상자를 표시하지 않는다.
- 서버를 같은 배포 URL의 새 버전으로 배포한 뒤 `index.html`, `vote.js`, `vote.css`를 게시한다. 실제 투표 데이터를 만들지 않고 공개 상태 조회로 연결을 확인한다.
- `node --test tests/*.test.cjs`는 가짜 저장소와 시각으로 마감 전/정각, 중복 제출, 결과 비공개와 집계를 검증한다.

## 유령 추첨

`Raffle.gs`는 비밀 정보가 없는 서버 코드다. Apps Script 프로젝트의 같은 파일을 교체한다.
기존 `Gift.gs`에는 다음 연결 함수를 유지한다. 저장된 이미지 상수는 사용하지 않으며,
어떤 API에서도 이미지를 반환하지 않는다. 실제 선물은 운영진이 당일 직접 전달한다.

```js
function giftAction(q) {
  return raffleAction(q);
}
```

`Code.gs`의 `handle()`은 이미 ScriptLock을 잡은 상태에서 이 함수를 호출하며,
`isAdmin(q)`로 기존 운영진 비밀번호를 검증한다. 해당 파일과 실제 기프티콘을 저장소에 올리지 않는다.
기존 웹 앱 배포를 새 버전으로 업데이트하여 URL을 유지한다. 서버 배포 후 클라이언트를 배포한다.

- 한국시간 2026-10-31 00:00:00 전에 서버가 받은 횟수만 집계한다. 별도 트리거는 필요 없다.
- 비밀번호 없이 이름만 선택한다. 100회 미만 진행도 저장하며 100회마다 자동 응모, 이름별 최대 다섯 장이다.
- 버전 3의 이름별 기록은 수정하지 않고 합계의 시작값으로 읽는다. 구버전 로컬 횟수는 최댓값으로 병합한다.
- 새 페이지마다 무작위 세션 ID와 해당 페이지의 누적 클릭 수를 전송한다. 이것은 인증 정보가 아닌 재전송 중복 방지용이다.
- 세션별 한 속성에 최댓값을 저장하고 이름별로 합산하므로, 여러 브라우저의 클릭은 더해지고 같은 요청 재시도는 중복되지 않는다.
- sessionStorage는 새로고침 시 미전송 횟수 복구에만 사용한다. 저장소가 없어도 현재 페이지에서 참여할 수 있다. 카톡에서 저장소가 초기화되면 이름만 다시 선택해 서버 기록을 이어간다.
- 클릭은 잠시 멈췄을 때, 20회 단위, 화면을 닫을 때 전송한다. 서버 저장이 확인되기 전에 화면이 강제로 종료되면 미전송 횟수는 복구되지 않을 수 있다.
- 마감 후 `#admin`에서 추첨하며 결과와 응모권 스냅샷을 한 번 저장한다. 재추첨 API는 없다.
- 기존 `gift` 지급 기록과 이미 저장된 추첨 결과는 보존한다. 과거 `claim`, `view`, `enroll`, `sync`로 새 지급·횟수 변경은 할 수 없다.
- 친구끼리 신뢰하고 참여하는 행사다. 이름 본인인증이나 클릭 조작 방지는 하지 않는다. 마니또의 비밀번호·암호화는 그대로 유지한다.

`node --test tests/raffle*.test.cjs`로 가짜 저장소·시계·기프티콘을 사용해 검증한다.
실서버에 응모·추첨 테스트 요청을 보내지 않는다.

# 할 일 카드 색상

카드는 `cream`(크림), `yellow`(노랑), `mint`(연두), `lavender`(라벤더) 중 하나를 `color`에 저장한다.
색 정보가 없는 기존 카드는 운영진만 노랑, 나머지는 크림으로 표시한다.
`Code.gs`의 `case 'board'`에서 `else return fail('bad_op');` 바로 앞에 아래 분기를 둔다.
기존 `setJ('board', b)`와 ScriptLock을 통해 다른 카드 수정과 함께 저장한다.

```js
      else if (op.type === 'setColor') {
        if (!t) return fail('not_found');
        if (['cream', 'yellow', 'mint', 'lavender'].indexOf(op.color) < 0) return fail('bad_color');
        t.color = op.color;
      }
```

색 변경은 이름 추가/빼기나 카드 삭제와 독립적이다. 운영진 카드도 색을 바꿀 수 있고, 삭제 제한은 유지한다.
색상 선택은 카드 머리의 작은 '색' 버튼에 접어둔다. 한 카드의 팔레트만 열리며 색을 고르면 자동 저장 후 닫힌다.

# 도착 예정 시간

`board.arrivals`는 참가자 index 0~10 순서의 배열이며, 값은 미정인 `null` 또는 13~19시다.
19는 '19시 이후'를 뜻한다. 기존 board에 배열이 없어도 빈 시간표로 표시한다.
`Code.gs`의 같은 `case 'board'`에서 `bad_op` 분기 바로 앞에 다음을 추가한다.

```js
      else if (op.type === 'setArrival' || op.type === 'removeArrival') {
        const i = idx(op.i);
        if (!Number.isInteger(op.hour) || op.hour < 13 || op.hour > 19) return fail('bad_hour');
        if (!Array.isArray(b.arrivals)) b.arrivals = Array(N).fill(null);
        if (op.type === 'setArrival') b.arrivals[i] = op.hour;
        else if (b.arrivals[i] === op.hour) b.arrivals[i] = null;
      }
```

이름 선택 후 시간대를 누르거나 이름을 끌어 놓으면 자동 저장하고, 배치된 이름은 위 선택 목록에서 숨긴다.
시간을 바꾸려면 이름 옆 ×로 취소한 뒤 다시 선택한다. 각 이름은 시간 하나만 갖는다.
취소는 요청에 담긴 시간과 현재 시간이 일치할 때만 적용해
다른 브라우저에서 방금 변경한 시간을 오래된 화면의 × 버튼이 지우지 않게 한다.
할 일과 동일한 ScriptLock과 저장 큐를 사용하며, 20초마다 다른 브라우저의 변경을 불러온다.

# 첫 연결과 로딩 표시

페이지 상단에서 `config.js`를 읽고 폰트 로딩보다 먼저 상태 요청을 시작한다.
최초 요청은 본문에서 재사용하고, 진행 중인 상태 요청은 중복해서 보내지 않는다.
할 일과 도착 시간에는 로딩 표시를, 6초 이후에는 지연 안내를 보여준다.
상태 요청은 18초에 종료하며 연결 실패 시 '다시 연결' 버튼을 제공한다.

성공적으로 받은 `board`만 localStorage에 7일간 캐시한다. 재방문 시 이전 목록을 먼저 표시하지만,
최신 응답이 도착하기 전에는 이름·색상 변경을 허용하지 않는다. API URL이 바뀌면 캐시는 사용하지 않는다.
마니또 비밀번호·개인키·매칭 결과는 이 캐시에 넣지 않는다. 저장소 사용이 막혀도 로딩과 재시도는 동작한다.
