# 사이트 통합 로그인 (2026-10-29)

- `Auth.gs`를 같은 Apps Script 프로젝트에 추가하고 `Raffle.gs`, `Third.gs`를 함께 게시한다. **비공개 Code.gs**의 `route(q)` 시작 부분에 아래 두 줄을 넣는다. `handle()`의 기존 ScriptLock 안에서 실행되므로 인증 확인과 데이터 수정이 한 요청으로 처리된다.

```js
function route(q) {
  const guard = authGuard_(q); if (guard) return guard;
  // 기존 switch (q.a)는 그대로 유지
```

- 첫 로그인 요청에서 `reg_<index>`의 `salt`와 `ver`만 `positive_auth_2026_<index>`로 복사한다. 비밀번호 원문, 개인키, 암호화된 결과, 마니또 실패 횟수는 복사하지 않는다. 사이트 계정이 존재하면 다시 복사하지 않는다. 사이트 초기화와 변경은 이 별도 계정 속성만 수정하므로 질문·투표·도착 시간·응모·마니또 데이터가 유지된다.
- 로그인·비밀번호 변경에는 기존 PBKDF2(SHA-256, 300000회, 512비트 중 뒤 32바이트의 SHA-256) 검증값을 사용한다. 새 비밀번호는 새 16바이트 salt를 사용한다. 이름은 서버 세션에 바인딩되며 임의 이름을 담은 요청은 거절한다.
- 임의 토큰은 서버에 SHA-256으로 저장하고 브라우저에는 로그인 토큰만 저장한다. 유효 기간은 14일, 이름별 최대 8개 브라우저 세션이다. 저장소 사용이 막혀도 현재 페이지에서 로그인할 수 있다. 카톡 저장소가 사라지면 재로그인이 필요하며 참여 기록은 서버에서 이어진다. 비밀번호·파생 검증값·마니또 복호화 결과는 브라우저 저장소에 넣지 않는다.
- 10회 로그인 실패 시 사이트 계정만 15분 잠근다. 운영진 진행실의 ‘사이트 비밀번호만 초기화’에서 사람과 임시 비밀번호를 입력하면 해당 사람의 사이트 세션을 모두 해제한다. 임시 비밀번호 로그인 후 새 사이트 비밀번호를 정하기 전에는 참여할 수 없다. 현재 비밀번호로 본인이 변경할 수도 있으며 다른 세션은 모두 해제한다. 어느 경우에도 마니또 비밀번호는 바뀌지 않는다.
- 마니또 확인에는 사이트 로그인과 기존 마니또 비밀번호가 필요하다. 사이트 비밀번호를 초기화해도 잊은 마니또 비밀번호나 암호화된 개인키를 복구하지는 못한다. 기존 마니또 초기화 기능은 별도 구역에서 매칭 재진행 경고와 함께 유지한다. 아직 마니또 미등록인 사람은 운영진이 사이트 임시 계정을 만든 뒤 로그인하여 마니또를 등록할 수 있다.
- 행사 안내·공개 현황은 로그인 없이 볼 수 있다. 할 일 참여/취소, 준비물 확인, 도착 시간은 본인 기록만 바꿀 수 있다. 할 일 카드 추가·색 변경은 로그인한 누구나 가능하며, 다른 사람이 배정된 카드 전체 삭제는 막는다. 투표·퀴즈·3등 게임·추첨도 로그인한 이름을 사용한다. 익명 조회에 이름을 붙여도 비공개 질문이나 개인 답안을 반환하지 않는다.
- 비밀번호 요청과 세션은 POST 본문으로만 보내며 URL에 싣지 않는다. 로그아웃/계정 변경 시 개인 화면을 지우고, 이전 로그인으로 시작된 늦은 응답은 폐기한다. 로그아웃 전에 미전송 유령 횟수 저장을 기다린다.
- 서버를 같은 URL의 새 버전으로 배포한 뒤 `index.html`, `auth.js`, `auth.css`, `raffle.js`, `vote.js`, `quiz.js`, `third.js`, `third.css`를 게시한다. 구버전 페이지는 새로고침해야 참여할 수 있다. 실제 계정 비밀번호를 바꾸거나 실제 투표를 제출하는 배포 테스트는 하지 않는다.
- `node --test tests/*.test.cjs`는 인증 복제·분리, 초기화 전후 기존 데이터 보존, 세션 만료·위조·다른 사람 사칭, 비밀번호 변경, 브라우저 재방문과 저장소 차단, 이전 응답 처리와 기존 게임 흐름을 가짜 저장소로 검증한다. `tests/fixtures/legacy-server.cjs`는 운영진 비밀번호를 가짜 값으로 교체한 기존 서버 테스트 사본이다. 실제 Code.gs는 저장소에 넣지 않는다.

기존 웹 앱 배포를 새 버전으로 업데이트하여 URL을 유지한다. 서버 배포 후 클라이언트를 배포한다.

- 한국시간 2026-10-31 00:00:00 전에 서버가 받은 횟수만 집계한다. 별도 트리거는 필요 없다.
- 통합 로그인한 이름으로 참여한다. 100회 미만 진행도 저장하며 100회마다 자동 응모, 이름별 최대 다섯 장이다.
- 버전 3의 이름별 기록은 수정하지 않고 합계의 시작값으로 읽는다. 구버전 로컬 횟수는 최댓값으로 병합한다.
- 새 페이지마다 무작위 세션 ID와 해당 페이지의 누적 클릭 수를 전송한다. 이것은 인증 정보가 아닌 재전송 중복 방지용이다.
- 세션별 한 속성에 최댓값을 저장하고 이름별로 합산하므로, 여러 브라우저의 클릭은 더해지고 같은 요청 재시도는 중복되지 않는다.
- sessionStorage는 새로고침 시 미전송 횟수 복구에만 사용한다. 저장소가 없어도 현재 페이지에서 참여할 수 있다. 카톡에서 저장소가 초기화되면 다시 로그인해 서버 기록을 이어간다.
- 클릭은 잠시 멈췄을 때, 20회 단위, 화면을 닫을 때 전송한다. 서버 저장이 확인되기 전에 화면이 강제로 종료되면 미전송 횟수는 복구되지 않을 수 있다.
- 마감 후 `#admin`에서 추첨하며 결과와 응모권 스냅샷을 한 번 저장한다. 재추첨 API는 없다.
- 기존 `gift` 지급 기록과 이미 저장된 추첨 결과는 보존한다. 과거 `claim`, `view`, `enroll`, `sync`로 새 지급·횟수 변경은 할 수 없다.
- 친구끼리 신뢰하고 참여하는 행사다. 로그인으로 이름을 확인하지만 클릭 조작 방지는 하지 않는다. 마니또의 비밀번호·암호화는 그대로 유지한다.

`node --test tests/raffle*.test.cjs`로 가짜 저장소·시계·기프티콘을 사용해 검증한다.
실서버에 응모·추첨 테스트 요청을 보내지 않는다.

# 할 일 카드 색상

카드는 `cream`(크림), `yellow`(노랑), `mint`(연두), `lavender`(라벤더) 중 하나를 `color`에 저장한다.
색 정보가 없는 기존 카드는 운영진만 노랑, 나머지는 크림으로 표시한다.
`Code.gs`의 `case 'board'`에서 `else return fail('bad_op');` 바로 앞에 아래 분기를 둔다.
기존 `setJ('board', b)`와 ScriptLock을 통해 다른 카드 수정과 함께 저장한다.

```js
      else if (op.type === 'setColor') {
        if (!t) return fail('not_found');
        if (['cream', 'yellow', 'mint', 'lavender'].indexOf(op.color) < 0) return fail('bad_color');
        t.color = op.color;
      }
```

색 변경은 이름 추가/빼기나 카드 삭제와 독립적이다. 운영진 카드도 색을 바꿀 수 있고, 삭제 제한은 유지한다.
색상 선택은 카드 머리의 작은 '색' 버튼에 접어둔다. 한 카드의 팔레트만 열리며 색을 고르면 자동 저장 후 닫힌다.

# 도착 예정 시간

`board.arrivals`는 참가자 index 0~10 순서의 배열이며, 값은 미정인 `null` 또는 13~19시다.
19는 '19시 이후'를 뜻한다. 기존 board에 배열이 없어도 빈 시간표로 표시한다.
`Code.gs`의 같은 `case 'board'`에서 `bad_op` 분기 바로 앞에 다음을 추가한다.

```js
      else if (op.type === 'setArrival' || op.type === 'removeArrival') {
        const i = idx(op.i);
        if (!Number.isInteger(op.hour) || op.hour < 13 || op.hour > 19) return fail('bad_hour');
        if (!Array.isArray(b.arrivals)) b.arrivals = Array(N).fill(null);
        if (op.type === 'setArrival') b.arrivals[i] = op.hour;
        else if (b.arrivals[i] === op.hour) b.arrivals[i] = null;
      }
```

이름 선택 후 시간대를 누르거나 이름을 끌어 놓으면 자동 저장하고, 배치된 이름은 위 선택 목록에서 숨긴다.
시간을 바꾸려면 이름 옆 ×로 취소한 뒤 다시 선택한다. 각 이름은 시간 하나만 갖는다.
취소는 요청에 담긴 시간과 현재 시간이 일치할 때만 적용해
다른 브라우저에서 방금 변경한 시간을 오래된 화면의 × 버튼이 지우지 않게 한다.
할 일과 동일한 ScriptLock과 저장 큐를 사용하며, 20초마다 다른 브라우저의 변경을 불러온다.

# 첫 연결과 로딩 표시

페이지 상단에서 `config.js`를 읽고 폰트 로딩보다 먼저 상태 요청을 시작한다.
최초 요청은 본문에서 재사용하고, 진행 중인 상태 요청은 중복해서 보내지 않는다.
할 일과 도착 시간에는 로딩 표시를, 6초 이후에는 지연 안내를 보여준다.
상태 요청은 18초에 종료하며 연결 실패 시 '다시 연결' 버튼을 제공한다.

성공적으로 받은 `board`만 localStorage에 7일간 캐시한다. 재방문 시 이전 목록을 먼저 표시하지만,
최신 응답이 도착하기 전에는 이름·색상 변경을 허용하지 않는다. API URL이 바뀌면 캐시는 사용하지 않는다.
마니또 비밀번호·개인키·매칭 결과는 이 캐시에 넣지 않는다. 저장소 사용이 막혀도 로딩과 재시도는 동작한다.
