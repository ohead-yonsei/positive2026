# 유령 추첨 배포

`Raffle.gs`는 비밀 정보가 없는 서버 코드다. Apps Script 프로젝트의 같은 파일을 교체한다.
기존 `Gift.gs`에는 다음 연결 함수를 유지한다. 저장된 이미지 상수는 사용하지 않으며,
어떤 API에서도 이미지를 반환하지 않는다. 실제 선물은 운영진이 당일 직접 전달한다.

```js
function giftAction(q) {
  return raffleAction(q);
}
```

`Code.gs`의 `handle()`은 이미 ScriptLock을 잡은 상태에서 이 함수를 호출하며,
`isAdmin(q)`로 기존 운영진 비밀번호를 검증한다. 해당 파일과 실제 기프티콘을 저장소에 올리지 않는다.
기존 웹 앱 배포를 새 버전으로 업데이트하여 URL을 유지한다. 서버 배포 후 클라이언트를 배포한다.

- 한국시간 2026-10-31 00:00:00 전에 서버가 받은 횟수만 집계한다. 별도 트리거는 필요 없다.
- 비밀번호 없이 이름만 선택한다. 100회 미만 진행도 저장하며 100회마다 자동 응모, 이름별 최대 다섯 장이다.
- 버전 3의 이름별 기록은 수정하지 않고 합계의 시작값으로 읽는다. 구버전 로컬 횟수는 최댓값으로 병합한다.
- 새 페이지마다 무작위 세션 ID와 해당 페이지의 누적 클릭 수를 전송한다. 이것은 인증 정보가 아닌 재전송 중복 방지용이다.
- 세션별 한 속성에 최댓값을 저장하고 이름별로 합산하므로, 여러 브라우저의 클릭은 더해지고 같은 요청 재시도는 중복되지 않는다.
- sessionStorage는 새로고침 시 미전송 횟수 복구에만 사용한다. 저장소가 없어도 현재 페이지에서 참여할 수 있다. 카톡에서 저장소가 초기화되면 이름만 다시 선택해 서버 기록을 이어간다.
- 클릭은 잠시 멈췄을 때, 20회 단위, 화면을 닫을 때 전송한다. 서버 저장이 확인되기 전에 화면이 강제로 종료되면 미전송 횟수는 복구되지 않을 수 있다.
- 마감 후 `#admin`에서 추첨하며 결과와 응모권 스냅샷을 한 번 저장한다. 재추첨 API는 없다.
- 기존 `gift` 지급 기록과 이미 저장된 추첨 결과는 보존한다. 과거 `claim`, `view`, `enroll`, `sync`로 새 지급·횟수 변경은 할 수 없다.
- 친구끼리 신뢰하고 참여하는 행사다. 이름 본인인증이나 클릭 조작 방지는 하지 않는다. 마니또의 비밀번호·암호화는 그대로 유지한다.

`node --test tests/raffle*.test.cjs`로 가짜 저장소·시계·기프티콘을 사용해 검증한다.
실서버에 응모·추첨 테스트 요청을 보내지 않는다.

# 할 일 카드 색상

카드는 `cream`(크림), `yellow`(노랑), `mint`(연두), `lavender`(라벤더) 중 하나를 `color`에 저장한다.
색 정보가 없는 기존 카드는 운영진만 노랑, 나머지는 크림으로 표시한다.
`Code.gs`의 `case 'board'`에서 `else return fail('bad_op');` 바로 앞에 아래 분기를 둔다.
기존 `setJ('board', b)`와 ScriptLock을 통해 다른 카드 수정과 함께 저장한다.

```js
      else if (op.type === 'setColor') {
        if (!t) return fail('not_found');
        if (['cream', 'yellow', 'mint', 'lavender'].indexOf(op.color) < 0) return fail('bad_color');
        t.color = op.color;
      }
```

색 변경은 이름 추가/빼기나 카드 삭제와 독립적이다. 운영진 카드도 색을 바꿀 수 있고, 삭제 제한은 유지한다.
